# Project Journey

This repository is an educational prototype for exploring longitudinal TTC alerts on an ESP32 and in Python.

## What is implemented

- Firmware source reads distance and wheel-encoder inputs, calculates TTC, updates LEDs and a buzzer, and emits the seven-field serial packet.
- Python tools provide a terminal demo, synthetic telemetry, serial reading, packet validation, replay, and a Streamlit dashboard.
- The repository includes a Wokwi circuit description and wiring documentation. A compiled Wokwi firmware image is not checked in; see [the simulation and Wokwi guide](dev/simulation-and-wokwi-validation.md).
- The optional training script fits a Random Forest for the dashboard and a threshold decision tree for C++ export. The firmware feature flag for the tree is disabled by default.

## Evaluation and limits

The checked-in dataset is generated by code, and its risk labels come from TTC rules. Training and evaluation now keep complete named scenarios apart. The current held-out metrics, including the rule baseline, are documented in [results](../results/README.md).

This validates data handling and model execution on synthetic scenarios only. It does not show real traffic performance, a physical build, or safety certification. A threshold-based model can reproduce labels generated from the same thresholds without demonstrating learned real-world prediction.

## Next steps

- Test the sensor and actuator wiring on a bench and document measured results.
- Capture a real Wokwi run after preparing the local build artifacts.
- Collect suitable real sensor data under controlled conditions before making performance claims.
- Evaluate any future changes on scenarios that were not used for training or model selection.
